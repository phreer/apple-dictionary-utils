# MDict 转换修复计划

## 目标

将系统 Apple Dictionary 词典稳定转换为可在常见 MDict 客户端中使用的
MDX/MDD，在内容、链接、样式、资源和检索入口之间取得可验证的兼容性。
“完全复刻 Dictionary.app”不作为近期目标，因为各客户端使用的 HTML/CSS
渲染引擎不同。

## 调研基线

当前 18 部普通词典共有 1,720,765 个词条，导出 XML 约 2.4 GiB。审计发现：

- 207,714 条查询链接和 756,038 条记录引用。
- 原实现会把资源目录中的全部 CSS 注入所有词条。例如《スーパー大辞林》的
  `VerticalStyle.css` 含有 `vertical-rl`，即使 plist 指定的是
  `DefaultStyle.css`，也可能令词典意外竖排。
- 原链接正则不能完整匹配含引号的 `xpointer`，并把链接末尾的回退标题错误地
  当作片段。约 65,127 条 Oxford 链接会产生多余片段，约 13,758 次精确词义
  锚点引用不能正确转换。
- 30,388 次内嵌图片引用占约 141.8 MiB。韩语词典中的 27,960 次引用实际只有
  346 个不同图片；其 Base64 数据从 134.7 MiB 去重后约为 1.8 MiB。
- 当前仅使用 `d:title` 生成 MDict key，尚未读取 `KeyText.index/data` 中的
  `DCSKeyword`、`DCSYomiWord`、词形和锚点索引。

## P0 实现范围

样式选择只读取 `DCSDictionaryCSS`。未声明样式时不自动猜测；声明的文件不存在
或 plist 无效时终止转换。附录词条自身显式引用的 `fbm.css` 仍会保留，其他
辅助样式会继续打包进 MDD，但不再全局启用。

链接转换支持以下形式：

- `x-dictionary:d:<查询词>` 转成 `entry://<查询词>`；
- `x-dictionary:r:<记录 ID>` 使用记录 ID 映射到目标标题；
- 带词典标识和回退标题的引用在目标 ID 缺失时使用回退标题；
- `#xpointer(//*[@id='...'])` 转成目标词条的 HTML fragment；
- 审计无法识别的 `x-dictionary` 链接时直接报错，不静默生成坏链接。

`audit_mdict_exports.py` 在不安装 `mdict-utils` 的情况下检查每部词典的 XML、
配置样式、查询链接、记录引用、未解析目标和缺失锚点。源词典本身可能含有少量
失效引用，因此未解析目标会进入报告，但不会让审计失败；结构或格式错误会失败。

## 后续阶段

### 显示兼容版

- 为 Apple 专用颜色、字体和 `apple_client` 选择器提供标准 CSS 回退。
- 以韩语、日语、简繁中文和 Oxford 词典建立代表性截图夹具。
- 将重复 Base64 图片写入 MDD，并把词条内 `src` 改写成资源路径。
- 在 GoldenDict-ng、一个官方 MDict 客户端和欧路词典中验证。

### 完整检索版

- 独立解析 Apple trie/heap 索引，不依赖 DictionaryServices 私有 API。
- 从 `DCSKeyword`、`DCSHeadword`、`DCSEntryTitle`、`DCSAnchor` 和
  `DCSYomiWord` 生成 MDict key 与 `@@@LINK=` 别名。
- 用 Dictionary.app 对照抽样验证中文拼音、日语假名、韩语和英语词形查询。

## 验收标准

- 18 部词典都能通过导出审计并完成打包。
- 默认只启用 plist 声明的样式，《スーパー大辞林》不再意外竖排。
- 转换结果中不残留支持范围内的 `x-dictionary` 链接。
- 所有已引用的 `xpointer` 都转换成正确 fragment；缺失目标或锚点在报告中可见。
- 回归测试覆盖双引号属性中含单引号的 `xpointer`、回退标题、缺失样式和样式选择。
- P1 完成后再以跨客户端截图作为显示兼容版的发布门槛。
